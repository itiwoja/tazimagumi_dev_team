# 推薦ロジック仕様書 v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §6](../specs/基本設計書_v1.0.md) ／ **関連：** [診断ロジック設計書 v1.1](../specs/診断ロジック設計書_v1.1.md)・[商品マスタ設計書](./商品マスタ設計書_v1.0.md)
**ステータス：** ドラフト

> 診断結果（6タイプ）＋予算帯から、**どの商品を候補に出すか**を決めるルールを定義します。
> 機械学習は使わず、**タグの絞り込みと並び替えだけ**の説明可能なルールベース。

---

## 1. 入力と出力

| | 内容 |
| --- | --- |
| **入力** | `diagnosis_result`（primaryType / secondaryType / isComposite）＋ 予算帯（`core`／`sub`） |
| **出力** | 概念（category）ごとの候補リスト（各概念で少数）＋ 比較トレイ用の最大3商品 |

---

## 2. 候補抽出ルール（`RecommendService.pickCandidates()`）

```
1. 対象タイプを決める
   - 単独：[primaryType]
   - 複合：[primaryType, secondaryType]（第二まで。⑥が第二なら単独）
2. products を絞り込む
   - type_tags が対象タイプを含む
   AND budget_tier が選択予算帯に一致（core選択時はcore+subも可）
3. category（概念）ごとにグルーピング
4. 各概念で並び替え（§3）→ 上位 N 件（MVPは各概念 最大3件）
```

### 2.1 予算帯の扱い

| 選択 | 抽出対象 |
| --- | --- |
| `core`（〜5,000円） | core ＋ sub（価格上限内の全件が対象） |
| `sub`（〜1,500円） | sub のみ（まず1本） |

> 基盤実装 `filterProductsByBudget()` と整合：core は全件、sub は `budget==="sub"` のみ。

---

## 3. 並び替え（優先順位）

同一概念内は次の順で並べる（上ほど優先）：

1. 対象タイプとの一致数が多い（複合時に両タイプ該当を上位に）
2. 予算内で安い順（初心者の心理的ハードルを下げる）
3. `summary_one_liner` が設定済み（説明できる商品を優先）

> スコアの重み付けや独自ランキングは持たない。**断定を避けるため**、並びは客観条件のみで決める。

---

## 4. 比較トレイ（`CompareService.buildTable()`）

- ユーザーが候補から**最大3点**を選んで横並び比較。
- 比較軸：**価格帯・容量・目的（category）・成分タグ（present の有無）・違いの一言**。
- 値が分かれる行を強調表示し、初心者が違いを掴めるようにする。
- 成分は「有無」のみ。安全/効能の断定は表示しない（[薬機法準拠ガイドライン](../guidelines/薬機法準拠ガイドライン_v1.0.md)）。

---

## 5. 複合タイプの表示

- メイン推薦（第一タイプ）＋サブ推薦（第二タイプ）を並列表示。
- 「最初は1本ずつ試す」旨を添える（診断ロジック設計書 §7 の文言を使用）。
- 3タイプ以上は表示しない（選択不能を防ぐ）。
