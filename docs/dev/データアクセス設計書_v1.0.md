# データアクセス設計書（API/データアクセス）v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §2.2 / §4](../specs/基本設計書_v1.0.md) ／ **関連：** [DB設計書](../design/DB設計書_v1.0.md)・[認証・データ保存方針書](./認証・データ保存方針書_v1.0.md)
**ステータス：** ドラフト

> データの取得・保存の方式を定義します。
> **MVPは外部API非依存・ローカルデータで動かす**。Supabaseは読み取り中心で段階導入。

---

## 1. データソースの2段構え

| 段階 | 商品・成分データ | ユーザーデータ |
| --- | --- | --- |
| **MVP（中間発表）** | `app/data/products.js`（`window.PRODUCTS`） | 端末ローカル（IndexedDB/localStorage） |
| **拡張** | Supabase `products` / `ingredients` を `supabase-js` で読み取り | 端末ローカルのまま（サーバ送信しない） |

- 中間発表は**確認済みローカルデータのみ**（デモ安定性／外部API非依存）。
- 楽天API・OCRはMVP対象外。

---

## 2. データアクセス層（リポジトリ）

データ取得を1か所に隠蔽し、MVP→Supabaseの差し替えを容易にする。

```
ProductRepository
  findAll()                    全商品
  findByBudget(budget)         予算帯で絞り込み（実装済み filterProductsByBudget）
  findByType(typeTags, budget) 推薦用の絞り込み（推薦ロジック §2）
```

- MVP実装：`PRODUCTS` をそのまま返す。
- 拡張実装：同じインターフェースのまま中身を `supabase.from('products').select()` に差し替え。
- 呼び出し側（画面・推薦）はインターフェースだけに依存する。

---

## 3. Supabase 接続（拡張時）

- `supabase-js` を `anon` キーで初期化（読み取り専用想定）。
- キーは `.env`（`VITE_`/グローバル変数）で管理し**ハードコードしない**。
- 失敗時はローカルデータにフォールバックし、ユーザーには簡潔なメッセージを出す。

```
読み取り例：
  const { data, error } = await supabase
    .from('products').select('*').contains('type_tags', [type])
  if (error) → ローカル PRODUCTS にフォールバック
```

---

## 4. レスポンスの扱い

- 商品取得結果は推薦ロジックが期待する形（[商品マスタ設計書 §1](../design/商品マスタ設計書_v1.0.md)）に正規化してから使う。
- 外部データは信頼せず、必須項目（id/category/price/budget/type_tags）の存在を検証。
