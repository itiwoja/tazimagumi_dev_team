# 状態管理・ルーティング設計 v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §2](../specs/基本設計書_v1.0.md) ／ **関連：** [画面設計書](../design/画面設計書_v1.0.md)・[コーディング規約](../guidelines/コーディング規約_命名規則_v1.0.md)
**ステータス：** ドラフト（基盤 `app/js/state.js` に準拠）

> 画面間でどう状態を持ち、どう画面を切り替えるかを定義します。
> MVPは**単一ページ（SPA的）＋共有状態オブジェクト**。ルータライブラリは使わない。

---

## 1. 単一の真実：`window.App.state`

```js
App.state = {
  current: "s1",      // 表示中の画面
  qIndex: 0,           // 初回チェックの設問番号
  answers: [...],      // 回答配列
  completed: false     // 初回チェック完了フラグ
};
```

- 状態は `App.state` に集約。各画面はここを読んで描画する。
- 更新は CORE の公開関数（`showScreen` / `pick` / `nextQuestion` 等）経由。**直接書き換えない**。

---

## 2. 画面ルーティング（タブ方式）

- 画面は4つ（`s1`〜`s4`）。`showScreen(id)` で `hidden` を付け替えて切替。
- タブは初回チェック完了まで②③④ロック。ロック中タップは toast で案内。
- URLは1枚（ハッシュルーティングはMVP外）。ブラウザ戻るは初回チェック内の「←」で代替。

```
showScreen("s2")
  → 全 .screen に hidden、対象だけ表示
  → state.current 更新 → updateProgress()
```

---

## 3. 進捗（プログレス）

- 初回チェック中：回答数 / 5 で 0.04〜0.25 を表示。
- 完了後：画面位置 / 4 で進捗を表示。
- `updateProgress()` が `--p` と `aria-valuenow` を更新（実装済み）。

---

## 4. データの受け渡し

| データ | 持ち主 | 使う画面 |
| --- | --- | --- |
| 回答・診断結果 | `App.state` ＋ ローカル保存 | ②③で参照 |
| 商品候補・予算帯 | `PRODUCTS` ＋ 選択状態 | ③ |
| 継続記録 | ローカル保存 | ④ |

- 永続化の媒体・キーは [認証・データ保存方針書](./認証・データ保存方針書_v1.0.md)・[DB設計書 §3](../design/DB設計書_v1.0.md)。

---

## 5. featureを足すときの原則

- 新機能は `screens.js` 以降に足し、`App` の公開関数を呼ぶ。
- CORE（`state.js` / `main.js`）は読むだけ。状態追加が必要なら村上に相談し公開関数を増やす。
