## 1. このアプリで解決すること

身だしなみを始めたい男性が、**最初の一歩で迷わず、買ったあとも続けられる**状態を作る。男性だけのチームとして、まずは自分たちが毎日使いたいと思える体験を優先し、卒制MVPでは範囲を絞る。

- **一言で言うと**：男の身だしなみアプリ
- **支える範囲**：身だしなみの「開始」から「定着」までの伴走
- **最終到達点**：ユーザーがケアを始めること。チームとしては、メンバー全員が何かしらの身だしなみ行動を始めている状態

## 2. なぜ男性向けか・誰のためか

- **対象**：身だしなみを始めたいが、何から始めるか分からない男性初心者（中心は10〜20代）。
- **背景（要点）**：男性化粧品市場は拡大基調にあり、若年男性が牽引層。一方で「何を選べばいいか分からない」状態は解消されていない。市場データの詳細・出典は `docs/research/report/` を参照。
- **男性特有の事情**：ひげ剃りによる肌負担、皮脂分泌の多さ、「美容について男性同士で話しにくい」心理的バリア。女性向けサービスでは取りこぼされている層が存在する。

### 現場ヒアリングからの示唆（上床先生インタビュー 2026-06-09）

- 男性は **根拠ベースの情報**（なぜ良いのか）に納得すると長く使い続ける → **成分など事実ベースの比較**が刺さる。
- 商品選びは **低評価レビュー**を重視、偽物・類似品に警戒、「ブランドが違うだけで成分がほぼ同じ商品」の情報が有効。
- 若い世代はコストをかけにくく、自宅ケアで土台を作る価値が高い（将来的にはサロンへの段階的導線も有効）。
- 詳細は [ヒアリング記録 2026-06-09](../research/interview_tajima_2026-06-09.md) を参照。

## 3. MVPの範囲

| 区分 | MVPでやること | MVPでやらないこと |
| --- | --- | --- |
| **開始** | 悩み・予算・生活習慣を確認し、今日から始める手順を提示する | 全ジャンルの美容知識を網羅する |
| **商品選び** | 初心者向けに最初の候補を少数提示し、違いを短く説明する | 外部API連携や大量SKUの自動収集 |
| **比較** | 価格帯・目的・成分タグなど、事実ベースで比較できるようにする | 安全/危険、効く/効かないの断定評価 |
| **定着** | 記録・再確認・リマインドで続けるきっかけを作る | SNS投稿、コミュニティ、サロン予約機能 |

## 4. 機能（MVP：4画面）

詳細仕様は [機能定義書 v1.0](./機能定義書_v1.0.md) を参照。

| 画面 | 対応REQ | 内容 |
| --- | --- | --- |
| **① 初回チェック** | REQ-01 | 肌・髭剃り・髪・眉・予算・生活習慣を短時間で入力 |
| **② 結果（ロードマップ）** | REQ-02 | 今日買う候補／今夜やること／明日の朝やること |
| **③ 商品候補・比較** | REQ-03/04/05 | 手動整備30-50商品から候補提示＋横並び比較＋成分タグ（事実提示） |
| **④ 継続記録** | REQ-06 | 週次の自己評価・再確認・リマインド |

**MVPでの約束**：ユーザーに「美容知識」を学ばせるのではなく、**3分以内に今日買う候補と今夜やる順番まで**決める。これを達成できない機能は中間発表の主役にしない。

---

## 5. 設計上の重要方針

- **ロードマップと商品の分離**：先に「何をすればいいか」を概念で示し（汚れ落とし→化粧水→乳液）、その後に「何を買うか」を具体的な候補で示す。
- **事実ベースの比較**：成分は「有無」という事実のみを表示し、安全/危険・効く/効かないの断定評価はしない。
- **最初の一歩のハードルを下げる**：継続機能に工数をかけるより、開始のハードルを極限まで下げることを優先（ミニマムルーティン＝朝夜30秒を前面に）。
- **デモ安定性**：中間発表では外部APIに依存せず、確認済みデータ（手動整備の30-50商品）で動作させる。

## 6. 非機能要件・制約

| 区分 | 要件 |
| --- | --- |
| **法令・表現** | 薬機法に抵触しないよう、効能や安全性の断定表現を避ける。成分は事実提示のみ、56効能の範囲内の表現に限定 |
| **プライバシー** | 写真などのセンシティブ情報はMVPではサーバ保存しない |
| **デモ安定性** | 中間発表では外部APIに依存せず、確認済みデータで動作させる |
| **保守性** | 商品データ・成分タグ・診断ロジックを差し替えやすく分離する |
| **使いやすさ** | 入力は短く、結果は3分以内に理解できる体験にする |

## 7. 使用予定技術

| レイヤー | 採用技術 |
| --- | --- |
| **フロントエンド** | React 19 + Vite + TypeScript + Tailwind CSS + shadcn/ui（PWAを主配信） |
| **BaaS / DB** | Supabase（Postgres + Auth + Storage + RLS）。MVPでは専用バックエンドを作らず `supabase-js` で接続 |
| **ロジック** | 診断スコアリング・ロードマップ生成はフロントのTypeScript純粋関数。複雑化時のみ Supabase Edge Functions を検討 |
| **商品データ** | MVPは `products` テーブルに30-50商品を手動整備。楽天API・OCRはMVP必須にしない |
| **画像保存** | 端末ローカル（IndexedDB / localStorage）のみ。サーバ送信しない |
| **アクセシビリティ** | WCAG 2.1 AA を意識（文字大きめモード、コントラスト比 4.5:1 以上） |
