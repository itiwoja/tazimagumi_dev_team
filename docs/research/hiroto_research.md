# 企画書 v3.0 に基づく調査結果

## 1. 最優先の懸念：楽天市場 API 移行の緊急性

**内容:** 企画書内では、楽天市場 API の旧版が 2026 年 5 月 13 日に廃止されると正確に把握されていますが、本日は 2026 年 5 月 12 日です。

**抜け目:** 明日が移行期限当日であるため、バックエンド担当のひろと氏は「今日中に」新版（accessKey + Referer/Origin ヘッダー認証）への切り替えと疎通確認を完了させていなければ、明日以降データ取得ができなくなるリスクがあります。

参照情報: [236], [448], [449]

---

## 2. 診断ロジックの科学的根拠の弱さ

**内容:** 23 問の診断項目（年齢、肌質、悩み、生活習慣、髭剃りスタイル）は網羅的です。

**抜け目:** スコアリングロジックが「別紙予定」となっており、現時点で「どの回答がどの成分（または商品）に紐づくか」の医学的・科学的根拠が企画書内で担保されていません。「専門家（薬剤師等）への確認」は開発工程の節目に行う計画ですが、診断の核となるアルゴリズム自体に専門家の監修が入っていないと、中間発表で「その診断結果は正しいのか？」という質問に窮する可能性があります。

参照情報: [325], [382], [398]

---

## 3. 「刺激配慮スコア」における法的リスクの残存

**内容:** v2.0 の「肌負担スコア」を「刺激配慮スコア」に改名し、表現を和らげています。

**抜け目:** 名称を変えても、アプリ側が成分組成から独自に「5 指標のスコア」を算出・提示する行為は、ユーザーに「安全性の保証」や「医薬的な効果の暗示」と受け取られるリスクが依然として高いです。特に「刺激が少ない」と断定的に表示することは、薬機法上の「効能効果の保証」に抵触する恐れがあります。

参照情報: [236], [345], [375]

---

## 4. データメンテナンスの運用コスト

**内容:** 200〜300 SKU の商品マスターを手動でキュレーションし、成分情報を転記する計画です。

**抜け目:** データ・コンテンツ担当のたかと氏 1 人で、300 商品の成分タグ付け・薬機法チェック・楽天 API から取得する価格/在庫情報の整合性を 11 月まで維持するのは非常に高い負荷となります。特に「髭剃り直後に刺激になりやすい成分」の判定を全商品に対して手動で行うのはミスが発生しやすいポイントです。

参照情報: [371], [384]

---

## 5. コミュニティ機能の「卒制後」の整合性

**内容:** 薬機法リスク回避のため、コミュニティを「学内クローズド・卒制期間限定」とし、終了後はアーカイブ化するとしています。

**抜け目:** 一方で、将来構想として「公開コミュニティへの拡張」を掲げています。中間発表では「卒業後の持続可能性（サステナビリティ）」を問われることが多いため、単に「閉じる」だけでなく、どのように安全な公開コミュニティへ移行するかのロードマップ（例：AI モデレーションの精度向上、運営体制の確保など）をもう少し具体化しておくと盤石です。

参照情報: [354], [369], [412]
