# 認証・データ保存方針書 v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §4.3 / §7](../specs/基本設計書_v1.0.md) ／ **関連：** [DB設計書 §3](../design/DB設計書_v1.0.md)・[データアクセス設計書](./データアクセス設計書_v1.0.md)
**ステータス：** ドラフト

> 「誰として使うか（認証）」「データをどこに置くか（保存）」の方針。
> **原則：ログイン不要で使える／センシティブ情報はサーバに送らない。**

---

## 1. 認証方針

| 区分 | MVP | 拡張 |
| --- | --- | --- |
| 利用開始 | **ログイン不要**（匿名）。診断・記録は端末内で完結 | 任意ログイン（端末間同期したい人向け） |
| Supabaseアクセス | `anon` キーで**読み取りのみ** | 同左。書き込みは管理者のみ |

- MVPはアカウント機能を作らない（離脱防止・実装簡素化）。
- ログインを足す場合も「ログインしなくても全機能使える」を維持。

---

## 2. 保存するデータと媒体

| データ | 媒体 | サーバ送信 |
| --- | --- | --- |
| 診断回答 `diagnosis_answers` | IndexedDB | しない |
| 診断結果 `diagnosis_result` | IndexedDB | しない |
| 継続記録 `continuity_log` | IndexedDB | しない |
| UI設定 `prefs`（文字大きめ等） | localStorage | しない |
| 写真などの画像 | 保存しない（MVP） | しない |

- **センシティブ情報（肌の悩み・写真）はサーバに保存しない**（プライバシー要件）。
- 商品・成分マスターのみサーバ（Supabase）に置く（読み取り）。

---

## 3. データのライフサイクル

- 端末内に保持。ブラウザのデータ削除で消える旨をアプリ内で軽く案内。
- 「もう一度はじめから」で回答をリセット（再診断）。
- バックアップ/エクスポートはMVP外。

---

## 4. セキュリティ上の注意

- Supabaseキーは `.env` 管理。リポジトリにハードコードしない。
- `anon` キーには書き込み権限を与えない（RLSで制限：[DB設計書 §4](../design/DB設計書_v1.0.md)）。
- ローカル保存データに個人特定情報（氏名・連絡先）は持たせない。
