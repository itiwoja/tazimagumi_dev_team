# 詳細設計書：累計記録の見せ方（累計日数表示） v0.1

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**対象機能：** S4 継続記録への「累計できた日数」表示
**版：** v0.1 / 2026-08-31（**チーム合意前の提案ドラフト**。実装決定ではない）
**根拠：** [プロダクト改善意見 v0.1](./プロダクト改善意見_v0.1.md) §1 強み2／[挫折させない設計 v1.0](../specs/挫折させない設計_v1.0.md) 原則1「抜けてもOK」
**関連実装：** `app/js/state.js`（`state.records`）／`app/js/screens.js`（S4 ドット描画）／`app/index.html`（`#s4` `.week` カード）

---

## 1. 目的と背景

- 本アプリの差別化軸は「抜けても戻ってこられる」こと（挫折させない設計 §0）。
- 一般の習慣化アプリは **連続日数（ストリーク）** を前面に出すが、途切れた瞬間にゼロへ戻るため喪失感を生む。これは原則1「継続を咎めない」と思想的に相性が悪い。
- そこで **「累計日数」（これまでにできた日の合計）を主指標にする**。累計は途切れても減らないため、復帰時に「積み上がったもの」が残っている体験になる。

## 2. スコープ

| やること | やらないこと |
| --- | --- |
| S4 に「これまでに ◯日できました」の累計表示を追加 | 連続日数・ストリークの表示（**導入しない**） |
| 累計を支える記録データの拡張（日付履歴） | 目標日数の設定・進捗バー（「あと◯日」は未消化を煽るので禁止） |
| 週次評価の既存UIはそのまま維持 | グラフ・カレンダー等のビジュアル積み上げ（将来検討。まず数値のみ） |

## 3. コピー設計（マイクロコピー統一 #71 に準拠）

| 場面 | コピー案 |
| --- | --- |
| 通常時 | `これまでに {n} 日できました` |
| 0日の時 | `記録はこれから。できた日がここにたまっていきます` |
| 久しぶりの復帰時 | `おかえりなさい。これまでの {n} 日はそのままです` |

- 禁止：「連続」「途切れ」「リセット」「あと◯日で達成」等の語（挫折させない設計 チェックリストに準拠）。
- 復帰時コピーは最終記録から一定日数（例：3日）経過時のみ差し替える。判定ロジックは純粋関数化する。

## 4. データ設計

### 4.1 state 拡張（**共有ファイル：state.js → 村上要相談**）

現状：`state.records = { todayDone: false, weekRating: null }`

```js
// 拡張案（後方互換を保つ）
records: {
  todayDone: false,
  weekRating: null,
  doneDates: [],        // "2026-08-31" 形式（YYYY-MM-DD・ローカル日付）の重複なし配列
  lastDoneAt: null      // 最終記録日（"YYYY-MM-DD" or null）。復帰判定に使う
}
```

- `doneDates` の長さがそのまま累計日数になる（`total = doneDates.length`）。**派生値は保存しない**（不整合防止）。
- `App.restore`（state.js）に後方互換ガードを追加：旧データに `doneDates` が無い場合は `[]` で初期化。既存の保存データを壊さない。
- 既存のエクスポート（設定「JSONで書き出す」）・全削除（Issue #85/#119）の対象に自動的に含まれることを確認する。

### 4.2 記録タイミング

- 現状の「今日のドット」操作（`todayDone` トグル相当）に連動し、`doneDates` へ当日日付を追加／除去する。
- 日付キーは **端末ローカルの暦日**（`toLocaleDateString("sv-SE")` 等で `YYYY-MM-DD`）。タイムゾーンまたぎの深夜記録の扱いは「端末の日付」を正とする（厳密な補正はしない）。

## 5. 画面設計（S4 への追記）

```
┌─ .week カード ──────────────┐
│ 今週の記録        抜けてもOK │
│ ● ● ○ ○ ○ ○ ○（ドット）   │
│ ─────────────────────────  │
│ これまでに 12 日できました    │  ← 追加（.week__total）
└────────────────────────────┘
```

- 追加要素：`.week` カード内のドット列の下に 1 行（新規クラス `.week__total`）。
- 週ドット（今週の事実表示）は変更しない。**主役は週ドットのまま**、累計は補助行として添える（原則2：情報を積み上げない）。
- スタイル：`style.css`（**共有ファイル→村上要相談**）。既存の `.week__sub` と同系統の控えめなサイズ・色。

## 6. ロジック設計

### 6.1 純粋関数（contracts.js or screens.js 内）

```js
/**
 * 記録履歴 → 表示用の累計情報
 * @param {{doneDates: string[], lastDoneAt: string|null}} records
 * @param {string} today  "YYYY-MM-DD"
 * @returns {{total: number, isReturning: boolean}}
 *   isReturning = 最終記録から3日以上経過 かつ total>0（復帰コピー判定）
 */
function summarizeRecords(records, today) { ... }
```

- 描画側（screens.js の S4 描画関数）はこの戻り値からコピーを選んで差し込むだけにし、分岐をUIに散らさない。

### 6.2 週ドットとの整合

- 現在の週ドット生成ロジック（screens.js）が週の日付配列を持つなら、`doneDates` を共通ソースにして「今週分」を filter する形に揃えると二重管理を避けられる。**既存ドット実装の読み合わせが最初のタスク**。

## 7. 挫折させない設計チェック（本機能の自己点検）

- [x] 記録の途切れを減点／喪失／叱責の表現で見せていない（累計は減らない／原則1）
- [x] 「あと◯日」等の未消化バッジ・目標を足していない（原則2）
- [x] リセット手段（全削除）は既存のまま、累計も一緒に消える（原則3・#85 と整合）

## 8. アクセシビリティ

- 累計行は `aria-live="polite"` を検討（記録操作直後に読み上げ）。
- 数値の色・大きさを「達成感の演出」として強調しすぎない（コントラスト比 4.5:1 以上は維持）。

## 10. テスト観点

- 同日に2回記録しても累計は1増のみ（重複防止）。
- 記録→アプリ再起動→累計が保持されている（永続化）。
- 旧バージョンの保存データ（doneDates 無し）で起動→エラーなく 0 から開始。
- 全削除→累計も 0 に戻る（Issue #119 の自動復活バグの再発がないこと）。
- 3日以上空けて起動→復帰コピーに切り替わる。連続していれば通常コピーのまま。
