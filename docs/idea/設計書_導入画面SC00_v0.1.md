# 詳細設計書：導入画面（SC-00） v0.1

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**対象機能：** 初回起動時の導入画面 SC-00 の追加
**版：** v0.1 / 2026-08-31（**チーム合意前の提案ドラフト**。実装決定ではない）
**根拠：** [プロダクト改善意見 v0.1](./プロダクト改善意見_v0.1.md) §2 提案C／[基本設計書 v1.0](../specs/基本設計書_v1.0.md) §3.1「SC-00 スタート／導入」（フルスペック設計の既知差分）
**関連実装：** `app/js/state.js`（`App.SCREENS`・画面遷移）／`app/index.html`（`#s1`）／`app/js/main.js`（初期表示）

---

## 1. 目的と背景

- 基本設計書 §3.1 で SC-00「スタート／導入」はフルスペックとして定義済みだが、実装MVP（4画面）では未実装のまま。
- M-MVP の GitHub Pages 公開後は **URL を開いた初見の人が S1 の質問にいきなり直面する**。「何のアプリか」「何をさせられるか」が分からないままの質問は離脱要因になる。
- 目的は3秒で伝えること：①何をするアプリか ②3分で終わること ③データは端末内だけであること。

## 2. スコープ

| やること | やらないこと |
| --- | --- |
| S1 の前に静的な導入画面を1枚追加（初回のみ表示） | チュートリアル複数枚のスワイプカルーセル（積み上げない） |
| 「はじめる」ボタンで S1 へ遷移 | アカウント作成・ログインの要求 |
| プライバシーひとこと表示（端末内保存の明示） | 利用規約への同意チェック（卒制スコープ外） |
| 2回目以降のスキップ＋設定からの再表示 | 動画・リッチアニメーション（軽量を維持） |

## 3. 画面設計

### 3.1 コンテンツ案

```
┌──────────────────────────┐
│      みだしなみ           │
│                          │
│  男の身だしなみ、          │
│  最初の一歩を決めるアプリ    │
│                          │
│  ・5つの質問に答えるだけ     │
│  ・今日買うものとやることが   │
│    3分で決まります          │
│  ・入力は端末の中だけに保存   │
│                          │
│     [ はじめる ]          │
│                          │
│  お試しなので、気軽にどうぞ  │
└──────────────────────────┘
```

- コピー原則：専門用語を使わない・断定しない（#71 マイクロコピー統一に準拠）。「お試し」表現で卒制プロトタイプであることを自然に伝える。
- ディスクレーマー（SC-99 相当）は S1 以降の既存配置のまま。SC-00 には出さない（「何をするか」に集中させる）。

### 3.2 遷移・表示制御

- **初回のみ表示**：`state.prefs.hasSeenIntro`（**state.js 拡張・村上要相談**）が未設定なら SC-00 を初期画面にする。「はじめる」押下で `hasSeenIntro = true` を保存し S1 へ。
- **2回目以降**：従来どおり保存済み `state.current`（または s1）へ直接復帰（`App.restore` の既存挙動を維持）。
- **再表示導線**（原則3：いつでも戻れる）：設定シートに「はじめの画面をもう一度見る」を追加（`hasSeenIntro = false` にしてリロード、または直接 SC-00 表示）。
- タブバー（1チェック〜4記録）は SC-00 では非表示または無効化し、プログレスも進めない（まだフローに入っていないため）。

## 4. データ設計

```js
// state.prefs に追加（後方互換ガード付き）
prefs: {
  hasSeenIntro: false   // SC-00 を見たか
}
```

- 保存・エクスポート・全削除は既存の永続化経路に自動的に乗る。
- `App.restore` に型ガード追加（`typeof saved.prefs.hasSeenIntro === "boolean"`）。

## 5. 実装方針（2案）

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **A（推奨）** | `section#s0` を新設し `App.SCREENS` に加えない独立扱い。初期表示時のみ main.js が `#s0` を出し、「はじめる」で非表示化して s1 表示 | `App.SCREENS`・タブ・プログレス等の共有ロジックに手を入れない。差し戻しも容易 | 画面遷移モデルの特例が1つ増える |
| B | `App.SCREENS = ["s0","s1",...]` に追加し正式な画面にする | 設計書（基本設計書 §3.1）と構造が一致 | タブ・プログレス・CTA・ロック等の全画面共通ロジックに影響。**state.js は村上一次管理**のため調整コスト大 |

- **案A を推奨**。基本設計書 §3 の「実装MVPとの差分」注記にも「SC-00 は未実装／フルスペック時の拡張」とあり、特例扱いは設計思想と矛盾しない。

## 6. 挫折させない設計との整合

- 原則2（1日1タスク）：SC-00 のアクションは「はじめる」1つのみ。
- 原則3（いつでも戻れる）：設定から再表示可能。S1 の既存「←」戻るボタンで SC-00 に戻る必要はない（情報画面なので戻る必然性が低い）。
- 「はじめる」を押さないと何も始まらない設計にしないため、スキップ導線（小さな「説明を飛ばして質問に進む」）を検討する。→ 初回は表示したいため、スキップは出さず「はじめる」のみ（1タップで抜けられるので実質スキップ）。

## 7. アクセシビリティ

- ページタイトル・h1 の整合：SC-00 表示中は「みだしなみ（アプリ名）」が見出し。
- 「はじめる」ボタンに autofocus は行わない（スクリーンリーダーが説明文を読む機会を奪わない）。Tab 順は説明→ボタン。
- 文字大きめモード・ダークモードで崩れないこと（既存トークンを使用）。

## 8. PWA・配信との関係

- Service Worker（`app/sw.js`）のキャッシュ対象に新規ファイルがあれば追加。**既存ファイル内への追記のみで構成すれば SW のバージョン更新のみで済む**（SW更新漏れは CI チェック対象）。
- 初回起動時のみの画面のため、オフラインでも完全動作すること（静的コンテンツのみ＝問題なし）。

## 10. テスト観点

- 初回アクセス（localStorage 空）→ SC-00 が表示される。
- 「はじめる」→ S1 へ遷移し、以降アクセスでは SC-00 が出ない。
- 設定から再表示 → SC-00 が出る →「はじめる」→ 現在の進行状態（s2 等）に戻れること（※再表示後は保存済み `state.current` へ戻す）。
- 診断途中でリロード → SC-00 は出ず、S1 の途中から復帰（既存 restore の回帰）。
- 全削除 → hasSeenIntro も消え、次回は SC-00 から開始（仕様として明記）。
