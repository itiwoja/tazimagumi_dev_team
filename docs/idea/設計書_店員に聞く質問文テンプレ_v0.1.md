# 詳細設計書：店員に聞く用の質問文テンプレ（F-14） v0.1

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**対象機能：** 診断結果から「店頭で店員さんに聞ける質問文」を生成・提示（F-14）
**版：** v0.1 / 2026-08-31（**チーム合意前の提案ドラフト**。実装決定ではない）
**根拠：** [プロダクト改善意見 v0.1](./プロダクト改善意見_v0.1.md) §2 提案B／[企画書 v6.1](../specs/企画書_v6.1.md) §2「美容について男性同士で話しにくい心理的バリア」／[機能定義書 v1.0](../specs/機能定義書_v1.0.md) F-14
**関連実装：** 用語ヒントシート（`app/index.html` `#sheet`）／`app/js/contracts.js`（`App.TYPE_META`）／`app/js/s3.js`

---

## 1. 目的と背景

- 企画書 §2 が挙げる男性特有の事情「美容について男性同士で話しにくい心理的バリア」。店頭でも「何を聞けばいいか分からない」が購買の直前の壁になる。
- インタビューでも「顧客の表向きの悩みと本音のズレ」（§4）が指摘されており、**自分の状態を言語化して渡せる**こと自体に価値がある。
- 固定テンプレ＋診断結果の差し込みという静的な仕組みのため、**外部API不要・デモ安定性を損なわない**。

## 2. スコープ

| やること | やらないこと |
| --- | --- |
| 診断タイプに応じた質問文テンプレ（3〜4本）の提示 | 自由入力の相談フォーム・チャット |
| 既存のシートUI（用語ヒントと同じパターン）での表示 | AI・LLM による質問文の動的生成 |
| コピー機能（クリップボード） | 店舗検索・店員への直接送信 |

## 3. コンテンツ設計

### 3.1 質問文テンプレ（たたき台。最終文言はたかとレビュー）

診断タイプ（`App.TYPE_META`）ごとに差し込む。以下は例：

| 対象 | 質問文案 |
| --- | --- |
| 共通 | 「初心者なのですが、化粧水と乳液は両方必要ですか？」 |
| 共通 | 「この商品の使う量・タイミングを教えてください」 |
| type1（皮脂） | 「皮脂が多めなのですが、さっぱり系の化粧水で十分ですか？」 |
| type2（乾燥） | 「洗顔後に肌がつっぱるのですが、乳液を足すのがいいですか？」 |
| type3（炎症） | 「赤みが出やすい肌なのですが、アルコールが入っていない商品はどれですか？」 |
| type4（髭剃り） | 「髭を剃ったあとにヒリヒリするのですが、剃った直後に使うものはありますか？」 |
| type6（入門） | 「まず1本だけ買うなら、オールインワンと化粧水のどちらがいいですか？」 |

- ルール：**使い方・違い・含有成分の事実を尋ねる文**に限定。「治りますか」「ニキビが消えますか」等の効能を尋ねる文は作らない（アプリが効能の期待を煽る構造を避ける）。
- 「私は〜です」という自己開示パーツを文頭に付けられる形にする（言語化支援が本機能の主目的）。

### 3.2 データ配置

- 新規ファイル `app/data/question-templates.js`（**data/ 配下なので共有ファイルではない**・たかとが一次管理）：

```js
window.QUESTION_TEMPLATES = [
  { id: "common-1", types: null,            text: "…" },  // types null = 全タイプ共通
  { id: "type1-1",  types: ["type1"],       text: "…" },
  { id: "type4-1",  types: ["type4"],       text: "…" }
];
```

- index.html の script 読み込み順に1行追加（data → state → … の data 群の末尾）。CSP は `self` 内なので変更不要。

## 4. 画面設計

### 4.1 導線

- 主案：**S3（商品比較）の比較表の下**に「店員さんに聞くときの例文を見る」リンクボタンを1つ。
  - 購買直前のタイミング＝S3 が文脈として自然。
  - 1画面1アクション原則に対し、主アクション（比較して選ぶ）を邪魔しない補助リンク。
- 副案：S2 ロードマップ末尾にも出す。→ **まずは S3 のみ**で検証（副案はユーザーテスト後に判断）。

### 4.2 表示

- タップで既存のシートUI（`#sheet` と同じ構造の dialog）を開く：
  - タイトル：「店員さんに聞くときの例文」
  - 本文：診断タイプに対応する質問文を 3〜4 本、箇条書きで。
  - 各質問文の横に「コピー」ボタン（`navigator.clipboard.writeText`）。
  - 末尾に1行：`例文はあくまで叩き台です。聞きやすい言葉に変えて大丈夫です。`
- シート実装は用語シート（#sheet）のパターンを流用し、新規シート `#questionSheet` を追加。既存 `#sheet` は用語表示専用のまま維持する（汎用化リファクタは行わない＝最小変更）。


- 選別ルール：タイプ一致を先頭2件、共通を後続2件。複合タイプ時は第一タイプのみ使用（情報量を絞る）。
- 配置：contracts.js 下部に追加（**共有ファイル→村上要レビュー**）。

## 6. 薬機法・表現チェック

- 質問文は「ユーザーが店員に尋ねる文」であり、アプリ自身の効能主張ではない。ただし §3.1 のルール（効能を尋ねる文を作らない）で、間接的な効能期待の煽りも防ぐ。
- 成分の言及は「入っていますか？」という**事実確認の文**に限定。
- 全テンプレの確定時にたかとが [薬機法準拠ガイドライン](../guidelines/薬機法準拠ガイドライン_v1.0.md) 照合を行う。

## 7. 挫折させない設計との整合

- 原則2：S3 の主アクションを増やさない補助リンク。質問文の「提出」等のタスクは存在しない。
- 原則3：シートは「とじる」で即座に戻れる。見ただけで状態は何も変わらない。

## 8. アクセシビリティ

- シートは `role="dialog" aria-modal="true"`（既存パターン踏襲）。フォーカストラップ・Esc 閉じを確認。
- コピー完了はトースト（既存 `.toast`）で「コピーしました」と通知。
- `navigator.clipboard` が使えない環境（非 HTTPS・権限拒否）では、質問文を選択可能なテキストのままにし、コピーボタンを出さないフォールバック。

## 10. テスト観点

- 6タイプそれぞれで、対応する質問文が表示される（複合タイプは第一タイプのみ）。
- コピーボタンで期待の文がクリップボードに入る（実機 iOS Safari / Android Chrome）。
- 非対応環境でコピーボタンが出ず、テキスト選択で代替可能。
- シートを閉じても S3 の比較選択状態が保持される。
- テンプレ全文中に「効く」「治る」等の禁止表現が無い（PR チェックに grep を追加する案あり）。

## 11. 未決事項

3. サロン版（床屋・美容室で聞く文）への展開は F-13 と統合して将来検討するか（本設計では対象外）。
