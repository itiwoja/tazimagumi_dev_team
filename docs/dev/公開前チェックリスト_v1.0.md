## 1. サブパス互換の静的点検結果（実施済み）

GitHub Pages はリポジトリ名 `tazimagumi_dev_team` のサブパス配下（`/tazimagumi_dev_team/`）で公開される。絶対パス（`/` 始まり）や `localhost` 決め打ちのURLがあると、サブパス配下では 404 になる。

| 対象 | 点検方法 | 結果 |
|---|---|---|
| `app/manifest.webmanifest` の `start_url` / `scope` | 目視確認 | ✅ `"./"` （相対）。サブパス配下でも正しく解決される |
| `app/manifest.webmanifest` の `icons.src` | 目視確認 | ✅ `"./icons/icon-192.png"` 等、すべて相対パス |
| `app/sw.js` の Service Worker 登録パス | `app/index.html` L381 を確認 | ✅ `navigator.serviceWorker.register("./sw.js")` — 相対パス |
| `app/sw.js` の `APP_SHELL`（キャッシュ対象） | 目視確認 | ✅ すべて `"./"` 始まりの相対パス（`./index.html`, `./css/style.css` 等） |
| `app/index.html` の `<link>` / `<script>` タグ | `rg '(src\|href)="/[^/]'` で絶対パス（`/` 始まり）を検索 | ✅ 該当なし（Google Fonts の外部URLを除き全て相対パス） |
| `app/js/*.js` 内の `fetch()` / `new URL()` / 絶対パス参照 | 全JSファイルを検索 | ✅ `debug.js` の `new URL(global.location.href)` のみ（現在地基準の相対解決のため問題なし）。ハードコードされた絶対パスなし |
| アイコンファイルの実在確認 | `app/icons/` を確認 | ✅ `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` すべて存在 |

**結論：現状のコードはサブパス互換の観点で修正不要。** 絶対パスに起因する公開後の404リスクは検出されなかった。

## 3. 公開実行の手順（#41・#43 完了後、人間が実施）

1. **Settings → Pages の有効化**（管理者操作・初回のみ）
   - GitHub リポジトリの Settings → Pages → Build and deployment → Source を **「GitHub Actions」** に切り替える
   - これが未設定だと `deploy-pages.yml` の Deploy ステップが失敗する
2. **develop → main のリリースPR** を作成し、レビュー後マージする（`main` への直接pushは保護ルールで拒否される）
3. マージをトリガーに `deploy-pages.yml` が自動実行される（`workflow_dispatch` での手動再実行も可能）
4. Actions の実行ログで `Deploy to GitHub Pages` ステップの `page_url` 出力を確認する
5. 実URL（`https://itiwoja.github.io/tazimagumi_dev_team/`）にアクセスし、S1→S2→S3→S4 の通しデモが動くか確認する
6. 問題なければ本Issue（#46）をクローズする
