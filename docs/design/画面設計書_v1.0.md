# 画面設計書 v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §3](../specs/基本設計書_v1.0.md) ／ **関連：** [UIデザインガイドライン](../guidelines/UIデザインガイドライン_v1.0.md)・[コンテンツ設計書](../guidelines/コンテンツ設計書_v1.0.md)
**ステータス：** ドラフト（基盤アプリ `app/` の実装に準拠）

> 基本設計書 §3 の4画面を、各画面のレイアウト・項目・ボタン挙動のレベルで定義します。
> 現状の基盤は **スマホ1枚（phone shell）に4画面をタブ＋プログレスで切り替える単一ページ構成**（`app/`）。

---

## 1. 共通レイアウト

```
┌─ phone shell ─────────────┐
│ appbar：ロゴ／ステップ表示  │
│ tabs：①初回 ②結果 ③くらべる ④記録 │
│ progress：進捗バー          │
├───────────────────────────┤
│ screen（スクロール領域）     │
│   各画面の本体              │
├───────────────────────────┤
│ dock：主CTAボタン（＋戻る）  │
└───────────────────────────┘
toast（一時通知） / sheet（用語解説の下からシート）
```

- **タブのロック**：初回チェック（5問）完了まで②③④はロック。タップ時はtoastで案内。
- **CTA**：画面ごとにラベルが変わる（下表）。
- **共通注意書き（SC-99）**：②結果・③くらべる の末尾に薬機法ディスクレーマーを常時表示。

## 2. 画面別 設計

### SC-01 初回チェック（F-01 / REQ-01）

| 項目 | 内容 |
| --- | --- |
| 構成 | 質問を1問ずつ表示（qcard）。選択肢はchip（タップで選択） |
| 進捗 | 「あと○問」表示＋プログレスバー。セクション完了で中間メッセージ |
| 分岐 | Q3で「ほぼ剃らない等」→ 髭剃り設問をスキップ |
| 検証 | Q9は1〜9件・「特にない」は排他。その他は1件必須 |
| ボタン | CTA「つぎへ」／戻る「←」。最終問→診断実行で②へ |
| 出力 | 6軸スコア → [診断ロジック設計書](../specs/診断ロジック設計書_v1.1.md) |

### SC-02 結果＝ロードマップ（F-02 / REQ-02）

| 項目 | 内容 |
| --- | --- |
| 上部 | 完了マーク＋判定タイプの一言 |
| 今日 | 「今日買う候補」カード（概念で提示・商品名は出さない） |
| 手順 | 「今夜やること」「明日の朝やること」を概念リスト（汚れ落とし→化粧水→乳液） |
| 用語 | 「○○ってなに？」をタップで下からシート（sheet）表示 |
| 分岐 | 複合タイプは両系統を提示（第二まで／⑥が第二なら単独） |
| 末尾 | SC-99 ディスクレーマー |
| CTA | 「具体的な商品の候補を見る」→ ③へ |

### SC-03 商品候補・比較（F-03/04/05 / REQ-03/04/05）

| 項目 | 内容 |
| --- | --- |
| 予算切替 | コア（〜5,000円）／サブ（〜1,500円）トグル。件数を即時更新 |
| 候補 | 概念ごとに少数候補（cand）。価格・容量・成分タグ |
| 成分タグ | 「配合あり／無香料」等、**有無の事実のみ**（tag--has / tag--free） |
| 比較 | 最大3点を横並び表（compare）。差がある行を緑で強調＋「違いの一言」 |
| 末尾 | factnote＋SC-99 ディスクレーマー |
| CTA | 「このまま記録を始める」→ ④へ |

### SC-04 継続記録（F-06 / REQ-06）

| 項目 | 内容 |
| --- | --- |
| ルーティン | 朝夜30秒のミニマムルーティンを再提示 |
| 今日の記録 | 「今日のドット」をタップで記録（toastで確認） |
| 週次評価 | 3択の自己評価（rate・単一選択） |
| リマインド | 端末内ローカル通知（サーバプッシュはMVP外） |
| CTA | 「もう一度はじめから見る」→ ①へ（再診断） |

## 3. 画面遷移

```
SC-01 →(診断)→ SC-02 →SC-03 →SC-04 ─┐
  ▲                                  │
  └──────── 再診断 ←─────────────────┘
タブで②③④に直接移動可（初回完了後）
```

詳細な遷移図は [基本設計書 §3.2](../specs/基本設計書_v1.0.md) を参照。

## 4. 状態とデータ受け渡し

- 画面間の状態は `window.App.state` を単一の真実として共有（[状態管理・ルーティング設計](../dev/状態管理・ルーティング設計_v1.0.md)）。
- 診断結果は②③で参照、記録は④でローカル保存。
