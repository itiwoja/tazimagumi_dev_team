# 商品マスタ設計書 v1.0

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**親：** [基本設計書 v1.0 §4](../specs/基本設計書_v1.0.md) ／ **関連：** [DB設計書](./DB設計書_v1.0.md)・[薬機法準拠ガイドライン](../guidelines/薬機法準拠ガイドライン_v1.0.md)
**ステータス：** ドラフト（基盤データ `app/data/products.js` に準拠）
**担当：** たかと（[DATA] 商品データ整備・30〜50件）

> 手動整備する商品データ（30〜50件）の**項目定義・入力ルール・禁止事項**を定めます。
> このマスターが推薦（F-03〜05）の土台。**事実だけを書く**のが最重要ルール。

---

## 1. 1商品の項目定義

| 項目 | 必須 | 例 | ルール |
| --- | --- | --- | --- |
| `id` | ✅ | `lotion-basic` | 半角英数とハイフン。一意 |
| `category` | ✅ | `化粧水` | 汚れ落とし／洗顔／化粧水／乳液／オールインワン／日焼け止め 等 |
| `name` | ✅ | `さっぱり化粧水 ベーシック` | 商品名（メーカー表記） |
| `price` | ✅ | `1320` | 税込価格（円・整数） |
| `volume` | | `200` | 容量（mL・整数） |
| `budget` | ✅ | `sub` | `core`（〜5,000円）／`sub`（〜1,500円） |
| `type_tags` | ✅ | `["type1","type4"]` | 対応タイプ。**複合対応で複数可** |
| `feel` | | `さっぱり` | 使用感（メーカー表記の事実） |
| `scent` | | `無香料` | 香り（事実） |
| `ingredients` | ✅ | `["セラミド配合","無香料"]` | 配合の**有無の事実のみ** |
| `summary_one_liner` | | `迷ったらコレ。さっぱり系の定番` | 初心者向け「違いの一言」 |
| `image_url` | | | 任意 |

> 現行 `products.js` は `id/category/name/price/volume/budget/feel/scent/ingredients` を実装済み。
> 本書で `type_tags` / `summary_one_liner` を**追加必須**とする（推薦・比較に必要）。

## 2. タイプタグ（type_tags）対応表

| タグ | タイプ | 主な該当カテゴリ例 |
| --- | --- | --- |
| `type1` | テカリ・皮脂 | さっぱり化粧水／皮脂対応洗顔 |
| `type2` | 乾燥 | 高保湿化粧水・乳液 |
| `type3` | ニキビ・肌荒れ | 低刺激・敏感肌向け |
| `type4` | ひげ剃り後の荒れ | アフターシェーブ系 |
| `type5` | くすみ・エイジング | 年齢肌ケア |
| `type6` | 初心者 | オールインワン1本 |

- 1商品が複数タイプに該当する場合は複数タグを付ける（例：低刺激な化粧水→ type2,type3）。

## 3. 成分タグの書き方（最重要・薬機法）

| ✅ 書いてよい（事実） | ❌ 書いてはいけない（断定） |
| --- | --- |
| 「セラミド配合」「ヒアルロン酸配合」 | 「ニキビが治る」「シミが消える」 |
| 「無香料」「アルコールフリー」「弱酸性」 | 「肌に最適」「効果保証」 |
| 「オイルフリー」 | 「安全」「刺激ゼロ」（安全性の断定） |

- 成分は**配合の有無**だけ。安全/危険・効く/効かないは一切書かない。
- 効能表現は化粧品の56効能の範囲内（[薬機法準拠ガイドライン](../guidelines/薬機法準拠ガイドライン_v1.0.md)）。

## 4. 整備の進め方

1. カテゴリごとに `core` / `sub` をバランスよく揃える（各概念で比較が成立する最低3件）。
2. まず30件を目標、最大50件。中間発表は**確認済みデータのみ**で動かす（外部API非依存）。
3. 入力後、価格・容量・成分表記をメーカー公式で**ダブルチェック**。
4. 完成データは `app/data/products.js`（MVP）→ 将来 Supabase `products` へ移送（[DB設計書](./DB設計書_v1.0.md)）。
