## 1. 結論

YouCam API は本アプリの題材との相性がよく、**任意の「AI詳細チェック」として小規模なPoCを行う価値がある**。

ただし、現在の5問診断を画像分析で完全に置き換えるのではなく、既存の質問診断に画像分析結果を加えるハイブリッド方式を推奨する。現行仕様では写真を外部サーバーへ送信しない方針になっているため、本導入にはプライバシー要件・同意画面・システム構成の見直しが必要である。

## 2. 利用候補機能

YouCam API には肌、顔、髪、ひげ、画像編集などのAPIがある。本アプリとの関連が強い候補は次のとおり。

| 優先度 | API・機能 | 本アプリでの利用案 |
| --- | --- | --- |
| 高 | AI肌分析 | 皮脂、水分量、毛穴、ニキビ、赤み、シワなどを補助スコアとして利用 |
| 中 | 髪タイプ・長さ・うねり・密度分析 | 将来の髪ケア機能や髪型提案の入力として利用 |
| 中 | ひげスタイル生成 | 身だしなみ提案の体験機能として利用 |
| 低 | 肌改善シミュレーション | 継続意欲の向上に使える可能性はあるが、効果を保証する印象や誤認に注意 |

AI肌分析APIは、写真またはカメラ映像から複数の肌項目を分析し、各項目のスコアやオーバーレイ画像を返す。公式ページでは、構造化されたJSON、REST API、Web SDK、JS Camera Kitへの対応が案内されている。

## 3. 既存診断との組み合わせ案

画像分析だけでは、髭剃り後の体感、予算、ケア経験、生活習慣などを判断できない。このため、現行の質問診断は残す。

```text
現在の5問診断
    ＋
任意の顔写真AIチェック
    ↓
既存6軸スコアを補助・補正
    ↓
ロードマップと商品候補を表示
```

想定する対応関係は次のとおり。実際の換算式と閾値は、PoC結果を見て別途定義する。

| YouCam APIの出力候補 | 既存診断タイプ・軸 | 扱い |
| --- | --- | --- |
| 皮脂・ツヤ | `type1` 皮脂 | 質問回答を補助するスコア候補 |
| 水分量・キメ | `type2` 乾燥 | 質問回答を補助するスコア候補 |
| ニキビ・赤み | `type3` 炎症・肌荒れ | 質問回答を補助するスコア候補 |
| 画像から直接判断しにくい | `type4` 髭剃り | 従来どおり質問で判定 |
| シワ・ハリ | `type5` 加齢 | 質問回答を補助するスコア候補 |
| 画像から判断できない | `type6` 初心者度 | 従来どおり質問で判定 |

初期PoCでは既存スコアを上書きせず、API結果を別枠で表示する方が安全である。結果の安定性とユーザー理解を確認した後、診断ロジックへの結合を検討する。

## 4. 現行仕様との主な差分

### 4.1 写真の外部送信

現行資料では、写真などのセンシティブ情報をサーバーへ送信・保存しない方針になっている。YouCam APIを利用すると、分析のために写真をPerfect Corp.側へ送信する必要がある。

公式ページにはアップロード写真を24時間以内に自動削除する旨が記載されているが、送信自体は発生する。このため、少なくとも次の対応が必要になる。

- AI詳細チェックを必須ではなく任意機能にする。
- 撮影・選択前に、送信先、利用目的、削除期間、アプリ側での保存有無を表示する。
- ユーザーの明示同意を得てからアップロードする。
- 同意しなくても既存の質問診断を利用できるようにする。
- プライバシーポリシー、要件定義、認証・データ保存方針を更新する。
- 写真およびレスポンスへ個人を特定できる情報を付加しない。

### 4.2 APIキーの保護

現在のアプリはHTML、CSS、バニラJavaScriptで構成された静的サイトである。ブラウザ側のJavaScriptにAPIキーを書くと、利用者がキーを取得できるため不可とする。

本導入時は、Cloudflare Pages FunctionsまたはCloudflare Workersを中継APIとして利用し、YouCam APIキーをSecretとして保持する構成が必要である。

```text
ブラウザ
  ↓ 写真（同意後）
Cloudflare Pages Function / Worker
  ↓ Secretで認証
YouCam API
  ↓ 分析結果
ブラウザへ必要最小限の結果のみ返す
```

中継側では、認証情報をログへ出さない、写真本文をログへ保存しない、リクエストサイズと回数を制限する、許可したAPI操作以外を呼べないようにする、といった対策も必要になる。

### 4.3 表現と免責

APIが肌状態のスコアを返しても、本アプリでは医学的診断として扱わない。

- 「医学的な肌診断」「病気を検出」といった表現を避ける。
- 「画像から推定される肌状態」「参考スコア」などの表現を使う。
- 「治る」「改善を保証する」「最適な商品」といった断定をしない。
- 既存の免責文を結果画面に継続して表示する。
- 強い炎症などが気になる場合は専門家への相談を案内する。

## 5. PoC案

公式ページでは、AI肌分析の初期テスト・統合向けに40クレジットが案内されている。まずは本番UIへ組み込まず、公式の[AI肌分析プレイグラウンド](https://yce.perfectcorp.com/api-console/ja/api-playground/ai-skin-analysis/)で検証する。

### 5.1 検証対象

- 公式のサンプル画像。
- 利用目的と送信先を理解し、明示的に同意したメンバーのテスト画像。
- 同一人物について、照明、角度、距離を変えた画像。
- 同じ画像を複数回送信した場合の結果。

実在人物の画像をリポジトリ、Issue、PR、チャットへ添付・保存しない。

### 5.2 確認項目

| 観点 | 確認内容 |
| --- | --- |
| 妥当性 | メンバーの自己認識や質問診断と大きく矛盾しないか |
| 再現性 | 同じ画像で結果が安定するか |
| 撮影条件 | 照明、角度、端末差でどの程度変動するか |
| 応答性能 | モバイル回線でも待ち時間が許容範囲か |
| 入力制約 | 対応形式、容量、解像度をアプリ側で案内できるか |
| 出力 | 必要なスコアがJSONで取得でき、既存6軸へ対応付けられるか |
| 費用 | 無料枠終了後のクレジット単価と、1回の分析で消費する量 |
| 障害時 | API停止・通信失敗時に5問診断へ戻れるか |
| プライバシー | 削除条件、保存場所、利用規約が卒制の方針に合うか |

### 5.3 PoCの合格条件案

- 同じ画像の繰り返し結果が、診断用途として説明可能な範囲に収まる。
- 撮影条件を画面上で案内すれば、大きな誤差を抑えられる。
- 既存診断に加えることで、ユーザーの次の行動が分かりやすくなる。
- 無料枠終了後の費用をチームが負担・管理できる。
- プライバシーと利用規約についてチーム合意を得られる。
- APIが利用できない場合も、既存の5問診断が正常に完結する。

## 6. 導入判断

| 判断 | 条件 |
| --- | --- |
| 採用 | PoC合格条件を満たし、プライバシー要件と運用費について合意できる |
| 限定採用 | 展示・デモ環境のみ、または希望者のみの詳細チェックとして提供する |
| 保留 | 精度は有望だが、料金・規約・写真同意の設計が確定しない |
| 不採用 | 結果が撮影条件で大きく変動する、費用を管理できない、現行方針と両立できない |

現時点の推奨判断は **「本実装は未決、プレイグラウンドによるPoCは実施候補」** とする。

## 7. 実装する場合のタスク候補

1. YouCam APIの利用規約、プライバシー条件、正確な料金、クレジット消費量を確認する。
2. 画像送信を含む要件変更についてチーム合意を取る。
3. 同意画面、撮影ガイド、キャンセル導線、免責表示を設計する。
4. Cloudflare Pages FunctionsまたはWorkerで最小の中継APIを試作する。
5. APIレスポンスを既存6軸とは別枠で表示する。
6. 撮影条件別の再現性テストを行う。
7. 合格後にスコア換算ルールを仕様化し、診断ロジックとの結合を検討する。
8. API障害時のフォールバックと利用回数制限を実装する。

## 8. 未決事項

1. 無料40クレジット終了後の正確な料金と、肌分析1回あたりの消費クレジット。
2. 卒制・教育目的での利用条件と、公開デモでの利用可否。
3. 写真および生成された分析データの処理地域、再利用条件、削除条件の詳細。
4. API結果を既存診断スコアへ加点するか、独立した参考情報として表示するか。
5. 肌分析、髪分析、ひげ試着のどこまでをプロダクトの中核に含めるか。
6. API呼び出し回数の上限、悪用対策、費用上限の設定方法。
