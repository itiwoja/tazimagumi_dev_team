# 挫折させない設計 v1.0（機能要件）

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**対象：** 全画面（S1〜S4）・全コピー・今後の feature 実装者
**関連：** [提案-U6] マイクロコピー統一（#71）／[コンテンツ設計書](../guidelines/コンテンツ設計書_v1.0.md)／Issue #91

> このアプリの差別化軸は「**初心者男性特化 × ゆるい継続**」。競合（多機能系美容アプリ）が
> 積み上げ・完璧主義で脱落者を出すのに対し、本アプリは「**抜けても戻ってこられる**」ことを
> 機能要件として定義し、全画面で一貫させる。

## 3原則

### 原則1: 抜けてもOK（継続を咎めない）

連続記録の途切れを、減点・叱責・喪失表現で表さない。復帰時は中立〜肯定のトーンで迎える。

- **やること**: 記録が飛んでも「ダメ」と言わない。ストリーク断絶の「連続◯日が途切れました」的な減点表現を使わない。
- **やらないこと**: 罪悪感を煽る通知、未達を赤字で強調する表示。
- **該当する既存実装**:
  - S4「今週の記録」見出しの補足 `今週の記録／抜けてもOK`（`app/index.html` `.week__sub`）
  - 記録ドットは「済み／なし」の事実表示のみで、なしを警告色にしない（`.dot--miss`）

### 原則2: 1日1タスク（積み上げない）

各画面で「今日やること」を1つに絞って提示する。ToDo を積み上げて未消化感を出さない。

- **やること**: 「今日はここまで」で区切る。1画面1アクションを基本にする。
- **やらないこと**: 未達タスクのバッジ数を出す、複数タスクを常時リスト表示して未消化を可視化する。
- **該当する既存実装**:
  - S2「今日やること」カード＝`洗顔のあと、化粧水を1本。今日はここまで。`（`app/index.html` `.today-card`）
  - S1 は1問ずつ表示するウィザード（`renderQuestion`）。残り問数コピーも「あと◯問・むずかしい言葉は出てきません」と負担を下げる（`screens.js` `remainCopy`）

### 原則3: いつでも戻れる復帰導線

どの状態からでも、やり直し・前に戻る・最初から、の導線を用意する。ロック中の要素も責めない文言にする。

- **やること**: 迷ったら戻れる。診断はいつでもやり直せる。
- **やらないこと**: 一方通行で後戻り不可のフロー、ロックを「未達だから使わせない」と突き放す文言。
- **該当する既存実装**:
  - 設定シートの「診断をやり直す（S1からやり直す）」（`#resetDiagnosisBtn`）
  - S1 の「←」戻るボタン（`main.js` `backBtn` / `App.prevQuestion`）
  - ロック中タブのツールチップ `初回チェックを終えると開きます`（突き放さず、開く条件を示す）

## 実装者向けチェックリスト（レビュー時に確認）

新しい画面・コピー・通知を追加するとき、以下に反しないか確認する。

- [ ] 記録の途切れ・未達を減点／喪失／叱責の表現で見せていないか（原則1）
- [ ] 1画面に「今日のアクション」が1つに絞られているか。未消化を煽るバッジ・リストを足していないか（原則2）
- [ ] その状態から「戻る／やり直す」導線があるか。ロック文言が突き放しになっていないか（原則3）
- [ ] マイクロコピーのトーンが既存（やさしい・専門用語を避ける）と揃っているか（#71 と連動）

---

## 現状コピーの点検結果（v1.0 時点）

S1〜S4・設定シートの既存コピーを3原則で点検した。**原則に反する表現は見当たらず**、思想は部分的に実装済み（上記「該当する既存実装」参照）。本ドキュメントは、それらを**明文化して今後の実装で崩さないための指針**として機能する。コピーの実変更は行っていない。
