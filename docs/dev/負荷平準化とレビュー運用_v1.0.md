## 提案1: データ整備の分担

- **#30（商品マスター）をカテゴリ単位で分割**し、調査だけなら誰でもできる形にする
  （例: 洗顔5件を新田さん、化粧水5件を田島さん…のようにテンプレCSVを埋める作業として配る）。
- **入力フォーマットを先に固定**する。本リポジトリに [`docs/data/商品マスタ入力テンプレ.csv`](../data/商品マスタ入力テンプレ.csv) を用意した。
  - 列は `app/data/products.js` の Product 型と一致: `id,category,name,price,volume,budget,typeTags,summary_one_liner,feel,scent,ingredients`（2026-07-17: `typeTags`・`summary_one_liner` を追加し、#54 マージ後の実スキーマに同期）。
  - `budget` は `core`（〜5,000円）/ `sub`（〜1,500円）のみ。
  - `typeTags` は**セミコロン `;` 区切り**で `type1`〜`type6`（複数可）。値は `app/js/contracts.js` の `App.TYPE_META` と一致させる。タイプ分類の事実のみで、効能・安全性の断定はしない。
  - `ingredients` は**セミコロン `;` 区切り**で複数記入（例: `セラミド配合;無香料`）。「配合の有無」の事実のみ。効能の断定表現は禁止（薬機法）。
- **検証と変換を前倒し**すると複数人入力でも品質が揃う:
  - #73 バリデーション（`scripts/validate-products.mjs`・本リポジトリにPR済み）で必須項目・薬機法表現を機械チェック。
  - #74 CSV→JS変換で `products.js` へ反映（`ingredients` の `;` 区切りを配列に展開）。
- **最終チェック（成分タグの正確性・薬機法表現）だけ仲程さんに集約**する。調査・一次入力は分散。

## 提案2: レビュー負荷の軽減

- **#81 PRチェックCI を最優先で入れる**（本リポジトリにPR済み）。機械で見られるもの
  （JS構文・データ検証・SWキャッシュ更新もれ・ブランチ名）は機械に任せる。
- **独立画面のPRは相互レビューでマージ可**にする:
  - 共有ファイル（`app/css/style.css`・`app/js/state.js`・`app/js/main.js`）に**触れていない**PRは、担当者以外の誰か1人のレビューでマージしてよい。
  - **村上さんの必須レビューは、共有ファイルを触るPRだけ**に絞る。
  - これによりSC-02〜04のUIなど独立PRが村上さん待ちで詰まらなくなる。
  - **2026-07-17時点の確認**: `CLAUDE.md`/`AGENTS.md` の「ブランチ保護ルール」節に、共有ファイル（`app/css/style.css`・`app/js/state.js`・`app/js/main.js`）や基盤に関わるPRのみ村上さんのレビューを待つ、という運用が既にPR #152で追記されている。本提案の趣旨とほぼ一致するが、**この提案書に対する明示的なチーム合意ログとしては未確認**のため、下記「完了条件」のチェックは付けていない。実質的にルールが機能しているかは村上さん自身に確認をお願いしたい。
