# 詳細設計書：NG成分登録→代替提示（F-12） v0.1

**プロジェクト：** 田島組 卒業制作（男の身だしなみアプリ）
**対象機能：** 避けたい成分の登録 → 該当成分を含まない候補の提示（F-12）
**版：** v0.1 / 2026-08-31（**チーム合意前の提案ドラフト**。実装決定ではない）
**根拠：** [プロダクト改善意見 v0.1](./プロダクト改善意見_v0.1.md) §2 提案A／[ヒアリング記録 2026-06-09](../research/interview_tajima_2026-06-09.md) §10「NG成分登録→代替商品提案」（優先度：高）
**関連実装：** `app/data/ingredients.js`／`app/data/products.js`（`ingredients` 配列）／`app/js/contracts.js`（`App.recommend`）／`app/js/s3.js`／設定シート（`app/index.html` `#settingsSheet`）

---

## 1. 目的と背景

- インタビューでの示唆：「石鹸でヒリヒリした原因成分を特定 → 代替品を提案」という形で、**体験と結びついた成分回避**は男性ユーザーに強く刺さる（§10）。
- 「この成分には注意」という形なら中立性を保てる、という整理済み（§10・企画書の薬機法ガードレールと整合）。
- 現状のデータ構造（商品ごとの成分タグ配列）は既に存在するため、**フィルタ条件の追加だけで実現できる**のが強み。

## 2. スコープ

| やること | やらないこと |
| --- | --- |
| 設定シートに「避けたい成分」チェックリストを追加 | 成分の危険度ランク・注意喚起スコアの表示 |
| S3 候補から「NG成分を含む商品」の除外（または折りたたみ） | 「この成分は危険」等の断定表現 |
| 除外で候補が減ったカテゴリへの「代わりの候補」提示 | NG成分の自動推定（「ヒリヒリした→アルコールでは？」等の推測はしない） |
| NG設定のローカル保存 | サーバ保存（既存方針どおり端末内のみ） |

## 3. 表現設計（薬機法ガードレール）

| 使う表現（許容） | 使わない表現（禁止） |
| --- | --- |
| 「避けたい成分」（ユーザー主語の選択） | 「NG成分」「危険な成分」（アプリが危険認定する表現） |
| 「選んだ成分を含まない商品だけを表示しています」 | 「安全な商品を表示しています」 |
| 「以前合わなかった成分がある場合に」（導入文） | 「アレルギー対策」（医療的効能の示唆） |

- 設定画面の項目名は **「避けたい成分を選ぶ」**。機能内部的な "NG" という語はUIに出さない。
- 皮膚科相談の導線（既存の `.safety` 文言）はそのまま併記する。
- 文言の最終確定はたかとが一次レビュー（[薬機法準拠ガイドライン](../guidelines/薬機法準拠ガイドライン_v1.0.md)）。

## 4. データ設計

### 4.1 設定の保存（**共有ファイル：state.js → 村上要相談**）

```js
// state に追加（後方互換ガード付き）
state.prefs = {
  // 既存（文字サイズ等）があれば維持
  avoidedIngredients: []   // ingredients.js の name 値の配列（例: ["アルコールフリー"] ではなく成分名）
};
```

- 保存先は既存の永続化（storage.js → localStorage）に乗せる。`App.restore` に `Array.isArray` ガードを追加。
- エクスポート／全削除（#85/#119）の対象に含まれることを確認。

### 4.2 成分マスタとの関係

- チェックリストの選択肢は `window.INGREDIENTS`（data/ingredients.js）から生成する。**選択肢は「成分系タグ」に限定**したい（「無香料」は避ける対象として成立するが、「低刺激」は避ける対象にならない）。
- 現状の INGREDIENTS には分類が無いため、**選択肢のホワイトリスト**（設定画面に出す成分の id 配列）を本機能側に持つ最小実装とする。ingredients.js への `category` 属性追加は将来検討（データ一次管理：たかと）。

## 5. ロジック設計

### 5.1 フィルタ関数（contracts.js に純粋関数として追加）

```js
/**
 * 商品リストから「避けたい成分」を含む商品を除く。
 * @param {Product[]} products
 * @param {string[]} avoidedIngredients  成分タグ名の配列
 * @returns {{visible: Product[], excluded: Product[]}}
 */
App.filterByAvoidedIngredients = function (products, avoidedIngredients) { ... };
```

### 5.2 推薦パイプラインへの組み込み位置

```
App.recommend(diagnosis, budget)
   ↓ （既存：タイプ×予算で絞り込み）
App.filterByAvoidedIngredients(...)   ← ここに挟む
   ↓
S3 描画
```

- `App.recommend` 自体のシグネチャは **変更しない**（共有契約の安定優先）。フィルタは `s3.js` の `App.renderS3` 内で `recommend` の結果に適用する。これにより contracts.js への変更は新規関数追加のみに留まる。
- **代替提示**：除外によりカテゴリの候補が 0 件になった場合、同カテゴリの `excluded` 以外の全商品（タイプ一致を外したもの）から価格昇順で最大1件を「代わりの候補」として提示する。

### 5.3 代替候補の表示文言

```
「（カテゴリ名）は、避けたい成分を含まない候補が見つかりませんでした。
 タイプは異なりますが、この商品は選んだ成分を含みません：{商品名}」
```

- タイプ不一致であることを必ず明示する（誤解防止）。

## 6. 画面設計

### 6.1 設定シートへの追加ブロック（index.html `#settingsSheet`）

```html
<div class="settings-sheet__block">
  <h4 class="settings-sheet__label">避けたい成分を選ぶ</h4>
  <p class="settings-sheet__note">以前合わなかった成分がある場合に。選んだ成分を含む商品は候補に出しません。端末内だけに保存されます。</p>
  <div class="settings-sheet__chips" id="avoidChips"><!-- INGREDIENTS から動的生成 --></div>
</div>
```

- UI は既存の chip パターン（S1 の `.chip`）を流用し、トグル選択式にする。
- 選択数の表示：「◯個を除外中」程度の事実表示。

### 6.2 S3 での状態表示

- 避けたい成分が1つ以上設定されている場合、候補見出しの下に1行：
  `「{成分名}」を含まない候補を表示しています（設定で変更できます）`
- 除外によって減った件数は表示しない（「◯件を除外しました」は出さない。無いものを数えさせない）。

## 7. 挫折させない設計との整合

- 原則1：関係なし。
- 原則2：S3 の主アクションは変えない。設定は任意の追加機能であり、未設定でも従来どおり動く。
- 原則3：設定の解除はいつでも可能（チップの再タップ）。「除外しすぎて候補が無い」状態からも、代替提示＋設定導線の文言で復帰できる。

## 8. アクセシビリティ

- チップは `aria-pressed` で選択状態を通知（S1 の chip と同パターン）。
- 設定シートは既存の dialog 実装（フォーカストラップ）に乗るため、追加の a11y 対応はチップ部分のみ。
- 除外状態の1行表示は `role="status"` で、S3 再描画時に読み上げられることを確認。

## 10. テスト観点

- 成分を1つ選択 → それを含む商品が候補から消える。
- 全解除 → 従来の候補に戻る。
- 某カテゴリが全滅 → 代替候補（タイプ不一致の明示付き）が出る。
- 未設定（初期状態）→ 既存と完全に同じ動作（回帰）。
- 設定→再起動→保持されている。全削除→設定も消える。
- UI文言に「危険」「安全な商品」等の禁止表現が無い。

## 11. 未決事項

1. 除外の扱いを「完全に非表示」か「折りたたみ（理由付きで残す）」か。本設計は **非表示** を採用（理由表示は「その成分を含む」事実の再提示であり、ユーザーが選んだ回避を邪魔しないため）。
2. 代替候補の提示上限（現状案：カテゴリあたり1件）。
3. 髭剃り後ケア（type4）など、成分タグが少ないカテゴリでの全滅頻度。実データでの事前試算が必要（たかと）。
